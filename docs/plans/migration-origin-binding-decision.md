# Migration origin binding decision

Status: proposed for named safety review; design only. Task task_18e5cbc6b5f9aa23, REQ-ORIGIN-1/2/3.
Source checkpoint: 2dee8a62; approved architecture: docs/plans/bridge-owned-runtime-local-search.md@1c83a464 §2 (line 33) and §7.4.

## Decision and trust boundary

Use a SEPARATE migration-only enrolled-device signature adopting an exact legacy-effect-to-executor mapping for the selected migration. Never extend local launch consent into a task grant. This permits fencing/reconciliation/import only; it cannot start, restart, nudge, merge, or otherwise execute task work.

The suggested authenticated source inventory plus Bridge signature is sufficient for explicit user-authorized attribution ONLY with the independent local evidence and completeness conditions below. It is not cryptographic proof that the historical unsigned command originated from legitimate task authority. An account-authenticated Hub response is transport/source-database evidence, not hostile-Hub-resistant provenance. Do not label it otherwise. Adding a Hub signing key would merely authenticate that same assertion and is rejected.

The signer must independently retrieve source rows and verify enrolled executor evidence over locally persisted raw command digests, actual parsed targets and native admissions. User confirmation must visibly identify selected chain, destination, affected devices/resources and unresolved items, and explicitly adopt that mapping. No arbitrary pasted Bridge metadata or caller chain labels. If original authenticated historical origin is required rather than explicit adoption, existing unsigned history cannot satisfy it: refuse, retain frozen/recovery state. This design does not manufacture missing history.

## Versioned wire records

NEW strict schemas, not claims about existing implementation. Use existing canonical field encoding/P-256 verification conventions, reject duplicate/unknown fields and noncanonical numbers, hash raw bytes with SHA-256. Lists are canonically sorted by complete identity, unique, bounded, with count and digest; truncated/paginated-unfinished responses cannot be signed as complete. Distinct canonical signing domains:

- migration-source-inventory-v1 (digest only, NOT a Hub authority signature): account, chain, migration ID, selection digest, source database identity, source fence revision, generation G, work revision, coverage start/version, closed-admission marker, effect count, executor set, resource set, effects digest. Every immutable effect row includes effect ID, command ID, kind, executor Bridge ID, generation, raw parent command digest; entry index + raw entry digest and parsed task/instance/lease identities for batched wakes. Mutable completion state belongs in later drain evidence, not this inventory digest.
- migration-executor-inventory-v1 (enrolled executor signature): account, migration, selection digest, source inventory digest, G, executor Bridge/key ID, incarnation, durable journal sequence, protocol/coverage version, fresh signer-generated observation challenge, observation time/expiry, complete local command/target/unknown sets and their counts/digests. Each mapping binds source effect+command+entry identity/raw digests to locally retained native admission, child launch key, instance/epoch/run/token-generation hash, configuration digest, protected directory ID/revision/key, canonical workdir hash, task and merge branch/repository identity as applicable. No secrets/raw tokens. A source row never seen locally is explicitly never-admitted with durable barrier/queue evidence, not silently omitted.
- migration-origin-binding-v1 (device signature): protocol version, account, principal/key ID, pinned directory root/head sequence/head hash/epoch, operation ID, issued/expiry, nonce, chain/migration, selected owner Bridge/key, selection digest, source inventory digest/revision/G, complete executor inventory digest set, complete mapping digest/count, purpose=adopt-for-migration-drain-only.
- migration-executor-drain-v1 (executor signature): all correlation fields above plus binding digest, barrier receipt digest, current incarnation/journal sequence, new challenge/time/expiry, exact inventory/mapping/resource digests, complete per-effect disposition digest, zero unresolved/admitted-handler/live-child/merge/queued-action counts and physical observation coverage digest.
- Final aggregate manifest is a DIFFERENT later digest: frozen source revision/G, selection/binding/drain-receipt digests, effective schema, row counts/content hashes and aggregate digest. Existing import/genesis/cutover proofs bind this final manifest.

## Signer checks and transaction order

1. Device verifies current enrollment chain against its pinned root/head, account and selected owner identity; signer must be current enrolled browser device explicitly consenting to migration, not merely possess a content key. Independently fetch source snapshot through account-scoped authenticated read, and executor challenge replies through encrypted transport with signatures verified against the same directory. Recompute all hashes; compare local raw-parent/entry/admission evidence with source rows. Reject substitutions, ambiguous merge retries, duplicate mappings, unexplained local targets or unknown coverage. Display exact adoption scope before signature.
2. SOURCE TX: authenticate existing migration selection; CAS expected work revision; persist draining state and block ALL new grants/effects/mutations for the selection. Serialize all producer paths with this fence (including reconnect, retries and nested transactions). Then persist immutable pre-drain inventory at G and source fence revision. Existing lease settlement/drain metadata may progress; they cannot add execution scope. Selection/draining is admission freeze; final frozen aggregate is later. Generation zero is valid for an empty source ledger but is NOT proof of empty historical execution.
3. No distributed transaction is assumed. SOURCE TX validates signed binding against current immutable snapshot, selection/G/revision and current enrollment, persists binding receipt with unique principal+operation and nonce/input digest. An exact replay returns historical receipt under current read authorization; changed bytes conflict. On a miss enforce expiry, nonce and CAS. Never clear fences on network failure.
4. EXECUTOR: verify device signature/current enrollment and independently compare binding to its retained signed observation and durable local evidence. Under established application/startup/physical gate ordering, recheck incarnation, journal sequence, actual targets and resource identity; CAS changes require a fresh observation/binding. Persist binding + full resource barrier atomically, waiting out earlier guarded invocations. Block delayed queued packets and all alternate instance/task/workdir paths by actual target, irrespective of incoming chain claim. A barrier acknowledgment is not drain.
5. Under retained barrier, reconcile every source effect and the UNION of local admissions, drafts, retained startup specs, daemon children, stops, merges, queues and protected resource users, including pre-upgrade survivors. Migration-only authenticated close operations may stop exact retained native keys; generic stop API is barred. Settle canceled-before-admission work without launching it. Observe physical absence after stop/merge termination; returned handlers, empty source leases and process-list guesses are insufficient. Sign complete drain evidence only when no uncertain or unaccounted execution remains. Shared resources remain fenced for every owning migration; another chain cannot remove protection.
6. SOURCE TX verifies all required executor drain signatures/correlation and source inventory coverage; CAS same G/revision, no live leases or outstanding effects, persist dispositions+drain receipts and frozen state atomically. A trusted device must also verify the complete receipt set before destination activation; a malicious Hub cannot bypass local barriers by lying about source state.
7. Export one consistent FROZEN aggregate and final manifest. Import into selected owner in one quarantined transaction, verify counts/hashes/IDs/authors and signed genesis/import receipt, then correlated source route CAS and activation per approved plan. Bind final manifest only here, never as a precondition to steps 1-5. Crash/retry stays fenced/quarantined; resume requires correlated destination retirement and new authenticated generation.

## Refusal, lifecycle and abuse checks

Missing pre-upgrade journal/admission/raw-digest evidence is UNKNOWN, not an empty inventory; no automatic backfill from Hub chain labels. Refuse unattended migration. Explicit offline recovery/reconciliation can establish physical absence but must record its separate evidence and cannot assert historical origin. Missing/offline executor, unverifiable complete executor set, unbounded pagination, storage errors, expired challenge, clock uncertainty, generation race, child/config/directory change, shared unaccounted child or uncertain merge all keep import blocked.

Refresh pinned directory before signing, accepting delayed evidence and each mutation. Bind exact device/Bridge key IDs and log head; require a verified extension, never rollback. Known revocation blocks new mutation and may hide replay bodies, while dedupe/tombstones and barriers survive. Rotation/re-enrollment/incarnation changes require fresh evidence and current authorization; retain old verification material for audit only. Signed-log freshness cannot defeat a malicious server withholding an unseen revocation: do not claim that guarantee; disconnected/uncertain freshness fails closed. Signatures do not establish truthful observations from a compromised enrolled executor or trustworthy UI on a compromised signer.

Encrypt detailed inventories, mappings and exports to authorized account devices/selected owner; Hub retains only necessary migration routing/CAS metadata. Do not disclose raw command tokens or command bodies. Hashes can leak low-entropy identifiers: protect them too. No new task grants or general Hub attestation endpoint.

Required implementation tests (focused, separate from physical guard/build results):
- Malicious Hub row/chain relabel with valid generic local-launch signature fails missing migration adoption/local raw match.
- Parent/entry mismatch, batched entry swap, repeated merge command with different effect ID, config/child/directory substitution fail.
- Omitted executor/effect, duplicate list, incomplete page, generation-zero plus pre-upgrade child, returned handler plus surviving daemon child fail completeness.
- Source G/revision changes; executor restart/journal change between observation and barrier; queued old command after barrier; shared resource bypass all fail closed.
- Crash at binding persist/barrier install/drain receipt/source freeze/export/import/route CAS; exact retry is read-only and altered retry conflicts.
- Revoked signer/Bridge, directory rollback, expired challenge, stale signature and uncertain clocks cannot newly mutate; historical replay cannot launch or release barriers.
