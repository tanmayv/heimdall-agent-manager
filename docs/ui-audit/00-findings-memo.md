# Findings Memo — Heimdall UI Audit

*Written last, placed first. The top 10 problems in `src/ui`, ordered by severity. Accessibility and
broken states rank above visual inconsistency, per the brief.*

Severity: **P0** = broken / blocks keyboard or SR users · **P1** = systemic inconsistency · **P2** = cleanup.

| # | Sev | Finding | Impact | Fix |
|---|---|---|---|---|
| 1 | **P0** | **No visible keyboard focus anywhere.** `focus-visible` appears in exactly **one** component (`ChatHoverCopyButton`). ~200 buttons rely on `hover:` only; inputs/selects/textareas set `outline-none` with no replacement ring. | Keyboard and low-vision users cannot see where focus is on a black UI — the app is effectively unnavigable without a mouse. Highest-severity, app-wide. | Build a single `focus-ring` token (`0 0 0 2px color-mix(accent…)`) into the `Button`/`Input`/`Select`/`Link` primitives via `:focus-visible`. Never allow bare `outline-none`. |
| 2 | **P0** | **Modals/menus have no focus management.** Of ~14 `fixed inset-0` overlays only **2** set `aria-modal`; none trap focus, restore focus on close, or handle Escape consistently. `role="menu"` popovers have no roving arrow-key focus. `ModalShell` is duplicated inline in `MemoryDetailPage`. | Screen-reader users can't tell a dialog opened; keyboard focus escapes behind the overlay; Esc doesn't close. | One `Modal` composite (portal + `role="dialog"` + `aria-modal` + focus trap + Esc + scroll-lock + focus restore) and one `Menu` (roving `tabindex`, arrow keys). Callers supply only content. |
| 3 | **P0** | **Non-semantic clickable + unlabeled controls.** `AgentListItem` row is a `<div onClick>` with no `role`/`tabIndex`/`onKeyDown` (`AgentListItem.tsx:94`) — the primary agent selector is keyboard-unreachable. Many icon-only buttons, chip-remove `×`, and bare-glyph buttons (`←`/`×`) have no `aria-label`; and emoji/text glyphs are used as icons (`🔍🎉✎🗑` in OnboardingWizard/ArtifactViewer/LibraryPage) without labels — also violating the project's own icons-not-emoji rule (AGENTS.md). | Keyboard/SR users can't select agents, remove chips, or understand glyph buttons; the app's core navigation is inaccessible. | Render interactive things as `<button>` (the `Button`/`IconButton`/`Card interactive` primitives enforce this). `IconButton.label` is required. Replace emoji/glyphs with named `<Icon>`. Remove stray `console.log` at `AgentListItem.tsx:79`. |
| 4 | **P0** | **Sub-11px text for real content.** ~100 uses of 8–10px text — folder counts `text-[8px]`, git/progress badges `text-[9px]`, delivery status `text-[10px]`, plus `text-[10px]` status pills. | Fails legibility/contrast expectations; unreadable for many users. | 11px floor via the type scale (`text-caption`). Snap all `text-[8/9/9.5/10/10.5px]` up. Live regions (`aria-live`) for status/errors, currently plain `<div>`s. |
| 5 | **P1** | **Three competing color systems.** A **dead** `odin.*` Tailwind theme (0 uses), the intended `--fd-*` CSS vars (used by 1 legacy file), and the de-facto raw Tailwind palette (`zinc ×1650, white ×1559, sky ×672, emerald ×201, amber ×183, red ×275`). Plus **4 different "accent blues"** for the same role and success expressed 3 ways. | Nothing can be re-themed; every screen picks its own values, so pages look unrelated. | Adopt the semantic token set (`02-tokens.md`). Delete `odin.*`. Pick one accent (`#0099ff`). Migrate raw utilities to tokens; lint against raw hex/palette. |
| 6 | **P1** | **No shared primitives — 469 hand-rolled `<button>`, 113 `<input>`, 95 `<select>`, 33 `<textarea>`.** "Primary" exists as `bg-sky-400/text-black/font-black`, `bg-sky-600/text-white/font-semibold`, `rounded-2xl/font-black`, and `rounded-full`; ~5 distinct "Send" buttons; danger split rose↔red (400/500 mixed). | The same atom is re-decided at every call site with 2px/one-shade differences — the direct cause of "every page feels different". | Ship `Button`, `Input`, `Textarea`, `Select`, `Link` primitives with `variant`/`size`. Codemod the highest-frequency shapes; lint-ban native `<button>` outside `Button`. |
| 7 | **P1** | **Every page rebuilds its own shell.** 4 distinct header dialects (`h2 text-xl font-semibold` vs `font-bold`+`text-xs` vs bare `h3` vs eyebrow+`h1 text-2xl`); content width varies across **10+** values (`max-w-3xl/4xl/5xl/6xl/2xl/md/[1600px]/[1360px]/[760px]/full`); headings use 6 sizes. `BridgesPanel` wraps itself in a card; `MemoryManagementPage` uses `rounded-3xl` cards while everyone else uses `rounded-2xl`. | Pages feel authored by different people; the user's #1 complaint. | Ship `PageShell` + `SectionHeader` + `Panel` layout set with a fixed content width token and one header structure. This is the single highest-leverage consistency fix. |
| 8 | **P1** | **Duplicated near-identical components.** Two full composers (`Composer.tsx` legacy + `ChatComposer.tsx`); three identical `Badge` helpers (`MemoryManagementPage`/`MemoryPage`/`MemoryDetailPage`); two `Empty` helpers; two `ModalShell`s; `MemoryScopeSelector` vs `memoryScope.ScopeEditor` implement the same control twice. | Fixes and a11y improvements must be made 2–3× and drift apart. | Promote to single `Badge`, `EmptyState`, `Modal`, `Composer`, `ScopeField`. Delete the deprecated twins (see mapping table). |
| 9 | **P1** | **Form controls fragmented + weak labelling.** Inputs come in 3 families (`bg-black/30 focus:sky-400`, `bg-black/40 focus:sky-500`, and the light/gray/blue `MemoryScopeSelector` outlier — the only theme-aware, `focus:ring` control in the app). Native `<select>`s are unstyled (OS chrome, variable dark contrast); many labels are siblings without `htmlFor`/`aria-label`. | Inconsistent look + programmatic label gaps hurt SR users and form UX. | One `Input`/`Select`/`Textarea` + `FormField` (label+hint+error, wired ids). Style native `<select>` consistently or wrap. Delete the gray outlier. |
| 10 | **P2** | **Undefined/dead tokens and ad-hoc scales.** `--fd-surface-3` referenced 12+× but **never defined** (renders transparent). Radius (8 values), z-index (`z-10…z-[90]`, ad hoc), shadow (~12), and motion (~10 durations) have no named scale. `spacing.84` one-off. | A live rendering bug (transparent surfaces) plus unmaintainable raw scales. | Define `surface-raised` (fixes the bug), adopt radius/z/shadow/motion tokens; lint against arbitrary values. |

## What this audit does NOT solve (honest limits)
- **Visual redesign.** Values are consolidated to what's already there; this is not a restyle.
- **The native `<select>` question.** Consistent styling vs. a full custom `Listbox` is a real
  trade-off (accessibility of native vs. control of custom) — flagged for a team decision, not decided here.
- **Third-party surfaces.** Vimee/Shiki editor, Mermaid diagrams, and the Markdown HTML-string
  renderer (`MarkdownBody.tsx`) inject their own styles; tokenizing them is a separate effort.
- **Runtime behavior / data.** Business logic, websocket/store wiring, and routing are out of scope
  except where they block the component API.
