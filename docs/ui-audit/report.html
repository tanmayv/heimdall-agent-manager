Design-systems audit · src/ui

Heimdall UI Inventory & Component API

The dashboard works, but it has grown organically — the same button exists in many forms and pages feel authored by different people. This audit finds the design language already implicit in the code, resolves its contradictions, and proposes a small component set to migrate to. No app code was changed.

Top findings (severity-ordered)

#SevFindingFix
1P0No visible keyboard focus anywhere — focus-visible used once; inputs strip outline-none with no ring.Build a focus-ring token into Button/Input/Select/Link.
2P0Modals/menus have no focus management — 2 of ~14 overlays set aria-modal; none trap focus or handle Esc consistently.One Modal/Menu with portal+trap+Esc+restore built in.
3P0Non-semantic clickables & unlabeled controls — AgentListItem row is a div onClick (keyboard-unreachable); emoji used as icons without labels.Render as <button>; require IconButton.label; named <Icon> only.
4P0Sub-11px text for real content (counts, badges, status) — fails legibility.11px floor via the type scale; snap all smaller sizes up.
5P1Three competing color systems + 4 accent blues + success three ways.Adopt the semantic token set; delete odin.*; pick one accent.
6P1No shared primitives — 469 <button>, 113 <input>, 95 <select>; "primary" has 8+ permutations.Button/Input/Select/Link primitives; codemod + lint-ban natives.
7P1Every page rebuilds its own shell — 6 header dialects, 10+ content widths, 2 card radii. The direct cause of "feels different per page."PageShell + SectionHeader + Panel with one width ramp & header.
8P1Duplicated near-identical components — 2 composers, 3 Badge helpers, 2 Empty, 2 ModalShells.Promote to one each; delete the twins.
9P1Form controls fragmented + weak labelling — 3 input families, unstyled native selects, sibling labels without htmlFor.Input/Select/Textarea + FormField wiring ids.
10P2Undefined/dead tokens — --fd-surface-3 used 12+× but never defined (renders transparent); ad-hoc radius/z/shadow/motion scales.Define it (fixes bug); adopt scales; lint arbitrary values.

Design principles: semantic props over stylistic (variant="danger", not color="red"); closed variant sets; accessibility built in, not a prop; one className escape hatch; a shared prop vocabulary so one name means one thing everywhere.

Migration — incremental, interruptible

  • W0 Tokens — ship the token set; delete dead odin.*; define --fd-surface-3 (fixes a live bug); pick one accent. Zero UI risk (1:1 mapping).
  • W1 Focus + a11y baseline — Button/IconButton/Input/Link with built-in focus rings. Fixes the #1 P0 across ~800 controls.
  • W2 Page shell — PageShell/SectionHeader/Panel; migrate pages one at a time → each is instantly on-model. Delivers the consistency goal.
  • W3 Overlays — Modal/Menu/Drawer with focus trap. Fixes the #2 P0 once, everywhere.
  • W4 Forms — Select/Combobox/Checkbox/Radio/Toggle/FormField; delete the gray shim.
  • W5 Status + feedback — Badge/StatusPill/Alert/EmptyState/Toast/Table/Pagination. Adds role=alert/status, real tables.
  • W6 Patterns + one-offs — merge composers, consolidate pickers, keyboard for the graph canvas.

Automation split: ~55% pure codemod (single-signature atoms), ~25% codemod+review, ~20% human judgement (intent mapping, page shells, overlays). Guardrails: lint-ban raw hex, arbitrary Tailwind values, native controls outside @ui/*, emoji-as-icon, outline-none without a ring, sub-11px text; axe a11y CI. Without these it re-fragments within two quarters.

Scope: src/ui only (Electron chrome & marketing page excluded). This is a consolidation of what already exists, not a redesign. Not solved: visual restyle · the native-select-vs-custom-listbox trade-off (flagged for a team decision) · third-party surfaces (Vimee/Shiki, Mermaid, the Markdown HTML-string renderer) · runtime/data/routing.
