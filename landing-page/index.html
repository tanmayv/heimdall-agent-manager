Architectural Guarantees

A native systems approach designed from the ground up for multi-device workflows.

Systems
Native Odin Binary
Compiled directly to native C-ABI machine code. Runs with zero external runtime dependencies—no Docker, Python, or Node daemons required on your host.
Footprint
~20MB Resident Memory
Runs silently as a native systemd user service (Linux) or launchd agent (macOS) with minimal host CPU and memory overhead.
Networking
Outbound-Only Tunnels
Bridges initiate outbound TLS WebSockets to the Hub. Traverses NAT and firewalls without opening inbound ports or running VPN clients.
Security
Client-Side 256-bit AES
Zero-knowledge encryption for all egress data. Prompts, diffs, and workspace secrets leave your machine encrypted with locally held keys (strict 0600 mode).
Reliability
Enforced Review Gates
Tasks follow a strict lifecycle. Autonomous workers cannot commit changes directly—independent reviewer agents must test and verify before merging.
Control
Work Alongside Fleet
Built-in file editor, native Git diff inspector, and streaming PTY terminals allow you to inspect, edit, or steer agents at any moment.

How Heimdall Works

A disciplined workflow for running autonomous AI agents on real codebases.

01 / FLEET

Bring Your Own Agents Across Devices

The Problem: Managing agents across your laptop, desktop, and cloud server requires juggling separate terminal windows, leading to context drift and lost changes.
Install the lightweight bridge on any machine with one command. Register and run any agent harness—Claude Code, Cursor, Antigravity, or custom scripts—under one unified dashboard.
  • Single-command node enrollment (`heimdall enroll`)
  • Universal PTY bridge supports any CLI harness
  • Multi-machine status and health diagnostics
02 / COORDINATION

Multi-Agent Coordination & Review Gates

The Problem: Solo agents operating in isolation hallucinate requirements, make assumptions without checking, and break existing tests.
Coordinator agents break objectives into structured task DAGs. Workers execute in parallel, and dedicated reviewer agents must independently test and cast verifiable LGTMs before changes land.
  • Living specification tracked inside task chain descriptions
  • Two-tier review protocol (QUICK vs COMPREHENSIVE)
  • Unanimous quorum auto-finalization engine
03 / SECURITY

Zero-Knowledge Security Architecture

The Problem: Centralized agent platforms store workspace credentials, repository code, and API keys in plaintext on remote cloud servers.
All data leaving your machine is wrapped in client-side 256-bit AES-GCM ciphertext (`vault:v1:...`). The central Hub coordinates tasks without ever seeing plaintext code or keys.
  • PBKDF2-SHA256 client wrapping key derivation
  • Strict POSIX 0600 file permission enforcement
  • Hub stores zero-knowledge encrypted envelopes only
04 / REMOTE

Zero-Config Remote Access

The Problem: Accessing your development machine or homelab on the go requires brittle SSH tunnels, dynamic DNS, or punching holes in firewalls.
Engineered from day one for remote development. Heimdall bridges establish secure outbound TLS WebSocket tunnels to the Hub. Access your fleet and terminals anywhere without VPNs or port forwarding.
  • 100% outbound-only WebSocket architecture
  • No SSH keys, router port opening, or VPN clients
  • Pick up active coding sessions from any browser
05 / PAIR PROGRAMMING

Work Alongside Your Fleet

The Problem: Black-box AI tools hide behind chat windows, disconnecting developers from their repository state until something breaks.
Full human-in-the-loop pair programming. Built-in syntax-highlighted editor, native Git VCS diff viewer, and low-latency interactive PTY terminals allow you to step in and guide agents in real time.
  • Native Git diff inspector with line-by-line review
  • Real-time terminal streaming via `ham-pty-host`
  • Interactive shell takeover and live signal delivery

Quick Start

Simple, predictable CLI for managing your local bridge and daemon lifecycle.

# 1. Install precompiled binaries (Linux / macOS) curl -fsSL https://get.heimdall.dev/install.sh | bash # 2. Configure local 256-bit Zero-Knowledge Vault Key (strict 0600 mode) heimdall vault set-key <64-character-hex-key> # 3. Enroll your host bridge with your central Hub heimdall enroll <one-time-token> --hub https://hub.yourdomain.com # 4. Check fleet connectivity and daemon status heimdall status heimdall doctor

Frequently Asked Questions

Details on self-hosting, remote access, and zero-knowledge encryption.

How does remote access work without SSH or VPNs? +
Heimdall bridges initiate outbound TLS WebSocket connections to your Hub. Because all connections are outbound, you can access your workstation or homelab agent fleet from anywhere without configuring router port-forwarding, dynamic DNS, or VPN clients like Tailscale.
How does Heimdall protect source code and secrets? +
Heimdall uses a Zero-Knowledge Vault architecture. Your Master Password derives a 256-bit AES-GCM wrapping key entirely in your client browser/UI. All data that leaves your local device is encrypted ciphertext (`vault:v1:...`). The Hub never sees plaintext prompts, code, or API keys.
Can I bring my own existing coding agents? +
Yes. Heimdall is completely harness-agnostic (Bring Your Own Agent). It seamlessly manages Antigravity, Claude Code, Gemini CLI, Cursor Agent, OpenCode, Aider, and custom agent runtimes through its universal PTY bridge (`ham-pty-host`).
Can I work alongside my agents while they code? +
Yes. Heimdall includes a built-in code editor, native Git VCS diff viewer, and interactive PTY terminal streaming. You can review intermediate diffs, make manual edits, or jump into an agent's shell at any time.
Does Heimdall require Docker or Kubernetes? +
No. Heimdall compiles to static native binaries with zero external runtime dependencies and runs as a lightweight user systemd unit (Linux) or launchd service (macOS) using ~20MB of RAM.
